# BUBBLES 语义调度：实验代码、结果与复现包

研究进行中，数字可能还会变。这里是到 2026-10-08 为止的代码、图表脚本、图表所用的结果文件和一套可直接重跑的复现包。

## 研究的问题

U-space 里按固定 4D 航迹做点巡检的无人机，把"相对参考图发生了什么变化"的证据经共享数据链回传地面。每架次的证据要在宽限时间内送达，并满足每架次的新增目标召回要求，否则就得悬停等待，悬停会挤占空域容量。

每个时隙、每架无人机，调度器决定两件事：证据只发符号层（机载检测结果，约 230 字节），还是加发图像 token（地面强模型复核）；以及它和哪条信道匹配。评价指标是**容量**：在拒绝率、航迹符合率、在空数、证据丢失率、每架次召回都达标的前提下，空域每小时能接纳的架次。

提出的方法是"结构化策略 + 强化学习"：策略形式固定为带紧迫度指数的 drift-plus-penalty 指标规则，只学两个结构参数（紧迫度指数 p、权重 V）。

## 目前的主要结果

测试流量（48 组，训练和调参都没用过）上的容量，单位架次/小时，"无缓冲 / 允许不超过 30 s 的时间缓冲"：

| 方案 | 3 条信道 | 4 条信道 | 5 条信道 |
|---|---|---|---|
| 提出的方法（10 次训练） | 40 / 40 | 60 / 60 | 65 / 65 |
| 网格搜索（同一策略族，56 个格点） | 40 / 40 | 60 / 60 | 65 / 65 |
| Drift-plus-penalty | 35 / 40 | 50 / 55 | 65 / 65 |
| H-PPO | 30（30–35）/ 35（35–40） | 50（50–55）/ 60（55–60） | 65 / 65 |
| D3QN | 30（20–35）/ 35（25–35） | 45（35–55）/ 50（45–55） | 65（50–65）/ 65 |
| TD3 | 15（<15–30）/ 30（20–35） | 25（<25–45）/ 45（40–55） | 40（<40–60）/ 65（60–65） |
| 固定档位 | 20 / 25 | 35 / 40 | 50 / 55 |

对比学习器是 5 个训练种子的中位数，括号里是范围。测试过的最高速率：3 条信道时为 40，其余为 65。完整的表在 `figs/out/tables.tex`。

怎么读这张表：

- 提出的方法**达到**网格搜索的水平，没有超过它。网格搜索是在同一策略族上、在一个工况上调出来的参照，不是全局最优。
- 提出的方法的优势在于不需要逐工况扫格点，以及相对无结构的学习器（H-PPO、D3QN、TD3）和不调参的规则，在无缓冲时容量更高。

## 已知局限

- **召回的绝对值低**。新增目标召回的上限由地面检测器决定：VisDrone 上未压缩图像只有 0.534，只发符号层是 0.397，所以召回要求取在 0.42–0.46。换成更容易的数据集（CARPK、HIT-UAV）上限能到 0.94–0.97，但机载小模型也几乎一样好，token 层就没有可补的量。这个问题还没有定论。
- **只有一个数据集**，重访图像对是合成的（抹掉部分目标后加配准误差）。
- **信道状态假设已知**；没有做不完美信道估计。
- **若干阈值是我们定的**：不达标架次不超过 5%、召回容差 0.005、最长地面等待 600 s。
- **单个 token 档位时学习器学不好**：在策略族内一档就够，但只剩二元选择时学出的策略等待明显变长；两档基本追平四档。原因没有做机理验证。
- **语义侧脚本只是归档**（`repro/stageA/`），没有在本包内重跑。
