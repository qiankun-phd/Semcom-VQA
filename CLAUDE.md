# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this workspace is

A **paper workspace** (not a git repo) for rebooting an IEEE TGCN manuscript:
*"Ask Before You Transmit: An Energy-Frugal Evidence-Level Semantic Communication System for UAV Visual Question Answering."*
Venue: IEEE Transactions on Green Communications and Networking. Manuscript in `paper/`, primary experiment code in `code/vqa_semcom_v0/`.

**Goal**: the current main line is considered weak. The work here is repositioning — generate repositioning options, possibly redo the literature review, and decide **keep / rewrite / drop** for each part of the old paper rather than defaulting to incremental edits. `paper_related/` holds sibling manuscripts for reference only, never as the main text.

It is a copy of `~/Documents/mpu/HPPO-VQA` + `HPPO-VQA-tgcn`, assembled so this rework can happen without touching the originals. Large datasets and `.git` history were not copied (see `code/DATASET_NOTE.md`).

## Rules

- **Never invent citations or numbers.** Some numbers in `paper/sections/06_experiments.tex` are still mock — search for `synthetic-mock` markers; they must be replaced with real data from aggregated run JSONs, never with plausible-looking values.
- When reworking a section, make the keep/rewrite/drop decision against the old paper explicit instead of silently blending old and new text.

## Layout

- `paper/` — the TGCN manuscript (main line). `main.tex` + `sections/01_introduction.tex` … `09_appendix.tex` + `refs.bib`.
- `paper_related/` — sibling manuscripts for reference only (`paper_hppo_tccn/` = MA-HPPO/TCCN line, `paper_rl/` = BUBBLES/RL line). Not the TGCN main text.
- `code/vqa_semcom_v0/` — main experiment code. **Has its own `CLAUDE.md`; read it before touching that subtree** (commands, JSON-not-YAML config, fixed service levels, frozen experiment-seed contracts).
- `code/hppo-uav/` — DI-engine fork (hybrid-PPO stack). Project-specific code lives in `dizoo/gym_hybrid/` (env + baselines), `ding/model/template/hppo_shared.py`, and `run/` (launch/eval/aggregate/audit scripts, `status.sh`).
- `docs/STATUS.md` — pipeline status: what's training where, working baselines, applied bug fixes, run-output layout, next steps. Check it before assuming experiment state.
- `docs/docs_spec/` — authoritative project report (`UAV_VQA_SemCom_System_and_Results_v6.html`, regenerated by `gen_report_v6.py`) plus positioning/novelty/citation-policy docs.
- `docs/plan_full/`, `docs/plan_tgcn/` — submission checklists, gates, audits (e.g. `tccn-submission-checklist.md`).
- `pdfs/` — compiled and conference PDFs; `reviews/` — reviewer comments (`审稿意见.docx`).

## Commands

### Compile the paper

```bash
cd paper
latexmk -pdf -outdir=build main.tex   # or pdflatex ×2 + bibtex
```

TGCN review format: IEEEtran 12 pt, single column, double spaced, ≤ 30 pages. Every figure goes through the `\evfig` macro, which is `\IfFileExists`-guarded — the document compiles even when figure PDFs are missing (a red placeholder appears). `\TODO{...}` and `\CITE{...}` macros render in red; grep for them before any submission pass.

### Figures

`paper/figures/` holds the figure PDFs, their generator scripts (`naturefig_f*.py`), and the CSV/JSON data they read. `figures/README.md` and `MANIFEST.md` map figure files → content → the remote server they were built on. Regenerate by running the matching `naturefig_*.py`; don't hand-edit the PDFs.

### Experiment code

```bash
cd code/vqa_semcom_v0
python -m unittest discover -s tests          # fast local regression (stdlib-only)
python -m unittest tests.test_v0_pipeline.V0PipelineTest.test_task_generator_creates_required_question_types  # single test
```

Full pipeline-stage and RL-adapter commands are in `code/vqa_semcom_v0/CLAUDE.md`.

## Split between this Mac and the lab servers

Heavy RL training does **not** run locally. It runs on two lab servers — S1 `lab-s1` (RTX 3080, pip-user Python 3.12) and S2 `lab-s2` (RTX 4060, conda env `DI-engine` / `RA_DI`) — under `~/HPPO-VQA/hppo-uav/`, with results in `~/HPPO-VQA/runs/`. Local work is: paper editing, figure generation, local unit tests, and pulling aggregated JSONs back via scp (recipes in `docs/STATUS.md`). `code/hppo-uav/run/status.sh` checks GPU/session/log state on both servers. Some scripts (e.g. `joint_control_rl_conditional_c1000.py`) import packages that exist only remotely and will not run on this Mac.

## Data flow paper ↔ experiments

Real numbers travel: remote runs → `run/aggregate_results.py` → `_aggregated_main.json` → scp to `paper/data/` → figure scripts → `paper/figures/*.pdf` → captions/headline numbers in `sections/06_experiments.tex`, Abstract, and §VII. When updating results, follow that chain rather than editing numbers in place.
