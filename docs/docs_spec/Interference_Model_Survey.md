# 多 UAV 上行干扰建模调研与口径决议（P7，2026-07-08）

> Opus 代理：先刻画我们实现（multi_uav_env.py 行级），再调研 10 篇文献，评判自洽性并给推荐口径。全文见代理报告，此为决议版。

## 我们实现的精确刻画

- 两趟法：先无干扰算链路，再 `_interference_dbm`（:2451-2471）汇总并发机干扰重算 SINR；
- 干扰 = 恒定底 -120dBm + Σ 并发上行机的 [min(B_i,B_j)/W_total] × overlap_scale × 干扰源功率×**其自身链路增益**（交叉增益近似，:2469）；
- overlap_scale：nominal 0.02 / interference-heavy 0.32（:171）——**无出处的经验旋钮**；
- 带宽份额进 Shannon 当专属带宽（正交读法），但同时产生重叠干扰（共道读法），**且 Σ份额无 ≤1 约束**；
- 干扰当噪声（无 SIC）、无闭环功控、噪声底 kTB+NF(7dB) 标准。

## 文献频率结论

| 模型 | 频率 | 代表 |
|---|---|---|
| 正交（带宽份额=RB 划分，零机间干扰） | **主流**（尤其 RL 带宽分配类） | Wu/Zeng/Zhang TWC'18 |
| 共道 interference-as-noise | 次高（功控 MARL 类） | Liu TWC'20 |
| NOMA+SIC | 少数 | Khairy JSAC'21 |
| 部分重叠加权（我们的对应物） | **小众**（WiFi/FANET POC 子域） | Fu'18, JEIT'24 |

**判决**：我们是"非标中间态"——中等审稿风险（"0.02 哪来的""正交还是共道"必被问）。

## 决议口径（推荐 b，a 为退路）

**(b) 主口径：共享频池 + 泄漏效率系数 ρ**（保留干扰）：
- 份额重述为"共享频池上的复用带宽"（**删除"专属/独占"表述**）；
- overlap_scale 正名为 ρ∈[0,1]（谱泄漏效率），两个极限有锚：ρ→0=正交主流（Wu'18）、ρ→1=全共道（Liu'20）；中间态引 POC（Fu'18/JEIT'24）；
- -120dBm 正名为干扰温度底 I_0；
- **ρ∈{0.02, 0.32} 包装为泛化实验轴**（env 已有 interference-heavy 训练场景 + test_interference_heavy 留出集——现成的故事）；
- 承认交叉增益近似（或改代码用受害侧增益）。

**(a) 退路：宣布正交**——去干扰项、SINR→SNR、加 Σshare≤1；若审稿人死磕 ρ 时降级用。

**System-model 段落措辞已由代理起草**（含公式 I_k = I_0 + ρ·Σ[min(B_k,B_j)/W]·p_j·g_j 与全部引用锚点），见代理报告第五节，论文二可直接改写采用。

## ⚠️ 2026-07-09 补正（链路审查发现，推翻上文"现成的故事"判断）

**主线 ρ 项是死代码**：`_interference_dbm` 只在 `concurrent_actions` 非空时累加，而该字段只有 smoke/benchmark 两个脚本填充；v19 训练/评测链每步只服务一个任务、从不填 → **主线干扰恒等于 I₀ 底**。interference-heavy 轴的实际差异来自 −116 dBm 底 + 6dB 快衰 + 0.7MHz 池，与 ρ=0.32 无关。若按 (b) 口径把 ρ 写成结果驱动因素属失实。

**修订后的推荐口径**：主线声明 "slotted 串行上行"（每步单任务上传是代码事实）+ 泛化轴改称 **I₀ 干扰底抬升轴**（−120→−116 dBm）；ρ/共享频池机制只出现在多机并发 benchmark 小节（`run_semantic_network_benchmark.py` 确实填 concurrent_actions，机制在那里是活的）。机内排队（E7v2 M/G/1）×机间频分需声明为两级互斥共享，避免双重计数争用。另：I₀ 名"温度"与实现（带宽无关常数）不符，改称"带外聚合干扰功率常数"或改 per-Hz；interference-heavy 的 6dB 高斯快衰与 LUT 内生 Rician 小尺度双重计数，需声明或去掉。
