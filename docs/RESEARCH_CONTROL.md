## 2. 固定研究目标，不固定实现手段

最终目标：在 VQA 正确率接近全图参考的条件下，降低实际通信量，并进一步验证整个系统的能耗收益。

当前阶段（EXP-014 已授权）回答：**增加新的训练图像与动作监督，并在较大的新测试集上，能否验证联合资源选择的泛化收益？** EXP-013 四组有局部变化但均未过筛选，不再按“尚未训练”立项。此次扩量包含同源小样本控制及公平训练的强单轴对照，不只增加轮数。EXP-010的RSVQA/T-DeepSC比较保留，但弱基线复核尚未解决。问题引导暂不新增训练。

- 全图输入是能力参考；同预算 JPEG 和普通神经压缩是竞争基线。
- 问题引导、TinyCLIP、LoRA、ROI、路由都是待验证的实现手段，不是必须保留的研究结论。
- 当前以真实编码、解码后的图像和图像码流字节为准；PNG 重建缓存、浮点特征大小、模型 token 数不能替代实际传输量。
- 按用户要求，现阶段先看图像编码字节，不把问题下行预算作为新的优化目标。但旧实验已经采用的总字节口径必须保留，不能事后改写为图像字节。
- 最终论文/系统的可接受准确率下降阈值尚未冻结；EXP-012 则已明确单独的探索筛选：相对4k/medium至多少对1题、图像字节至少省10%、效用超过强对照及种子一致性，不能事后放宽或当作最终非劣性证明。

## 3. 当前系统及证据状态

当前主线是图像重建接口：神经编码 → 实际码流 → RGB 重建 → Qwen 回答。不是直接把少量重建特征塞回 Qwen 内部。

基础模型为预训练 CompressAI `bmshj2018-hyperprior`（quality 3）与 Qwen3-VL-4B-Instruct；具体版本、训练模块及变体见[网络索引](NETWORK_RESULTS.md)。目前代码在服务器执行，UAV/接收端是拟部署的模块划分，不代表已经在 UAV 上测得时延或功耗。

|问题|当前可说的事实|不能升级成的结论|
|---|---|---|
|普通神经压缩是否值得保留？|EXP-005 的 600 题中，8k 总预算普通神经压缩为 466/600，JPEG 为 438/600；原图为 473/600|不能说所有 JPEG 实现都更差，也不是问题引导创新已经成立|
|问题门控是否有效？|多版训练/评测已完成；局部定位损失有小幅差异，但尚无稳定的端到端 VQA 增益|不能把定位 BCE 改善、码图变化或答案辅助候选上限当作可部署准确率提升|
|是否已经做接收端训练？|EXP-009 已完成两组 Qwen 语言层 LoRA 训练，各 300 次优化器更新|不是仅写好了代码，也不是编码器、门控与 Qwen 的联合训练|
|最新接收适配是否达标？|120 图开发集的主要 4k 对照：压缩混合训练 93/120，等训练量原图控制 95/120|不能因 2k 次要结果较好就宣称主要目标达成|
|独立测试完成了吗？|EXP-007 的旧 300 图复用了 EXP-005 的部分图像，已经评估；EXP-009 的新 300 图仍封存、未评估，清单与旧 300 图交集为零|不能把旧 300 图算作另一批全新测试证据，也不能拿旧测试集继续调参后称全新测试|
|通信可靠性与能耗呢？|这些近期评测主要是无噪声真实码流闭环；EXP-005 的能耗字段不可用|成功解码率不等于无线交付率；字节减少不等于全系统能耗已降低|

以上数字只在各自数据划分与预算口径内比较，详见[结果表](NETWORK_RESULTS.md)。

## 4. 已完成与未完成必须分开

已完成的工作包括：长边上限 320、保持比例的缩放控制（非强制 320×320）、同图多问题拟合诊断、目标切换诊断、真实 VQA 配 COCO 框监督、600 图端到端评测、对齐后的量化图训练、旧 300 图评测、区域选择器及其可靠性复核、最新 Qwen 压缩输入适配。

此前将“320 分辨率控制”或“32 图同图多问题诊断”列成尚未开展工作的说法不准确；对应证据已登记为 EXP-001/006。后续只能提出有明确变量变化的复验，不能再次按首次实验立项。

仍未得到的关键证据：

1. 在最新、隔离的数据划分上，问题引导编码相对同预算普通编码有可复现的 VQA 净收益。
2. 新接收器与问题引导码流组合后的受控比较，以及任务驱动的发送端/接收端联合训练是否有收益。EXP-009 尚未训练该发送端模块。
3. 新 300 图保留测试上的最终结果。
4. 加入统一信道后的交付率，以及发送、通信、接收全过程的实测能耗。

这些是证据缺口，**不表示本次已经批准或启动上述全部实验**。EXP-010 正在补基线适配与共同信道验证，不包含新的问题引导训练、UAV 部署或实测能耗。

## 5. 下一步如何决策

**最新授权（EXP-014）**：用户要求启动扩量。固定 [新协议](../code/vqa_semcom_v0/experiments/rgb_selector_large/protocol.json)：4800/1200/2400图和嵌套480控制，共96次小MLP拟合；最多50轮、patience8。由于val2014活动类容量不足，训练使用TDIUC train2014，验证/测试使用val2014并做图像隔离。九档离线推理先生成训练/验证监督，全部控制器与依赖冻结后才打开新测试。测试不选新赢家、不改门槛；实际启动状态单独记入总账。本轮24小时上限，不自动衍生新任务；不以样本增多预先保证显著提升。此授权替代下面EXP-013终点的“不自动扩量”，不改写旧结果。

**前序决定（EXP-012）**：联合路由在新验证为82/120、2147.37 B，在复用旧开发为88/120、2097.47 B；固定4k/medium分别82/120、3996.73 B与93/120、3996.43 B。省字节成立，但没有稳定超过学习式码率单轴，旧开发准确题损失超标。停止扩大该特征/控制器版本，随后完成[缓存诊断](../code/vqa_semcom_v0/experiments/rgb_joint_diagnostics/DIAGNOSTIC_SCOPE.md)，保持模型、原协议与封存测试不变。根据诊断证据授权了下述EXP-013，不无限增加训练轮次。

缓存诊断结论：训练480图只有84图存在九档正确性差异；从固定2k/low出发，新验证可救9题、旧开发可救12题，原joint只救1/2且误伤1/2。新验证同图动作AUC0.495，取消惩罚通信量升至7494 B却少对1题。首层输入尺度失衡是待控实验检验的风险，非已证明因果。详见[诊断报告](../paper/outputs/rgb_joint_selector_20260922/diagnostics/analysis-report.md)。

**最新授权（EXP-013）**：用户同意开始上述 2×2。训练前固定[协议](../code/vqa_semcom_v0/experiments/rgb_selector_factorial/protocol.json)：图像标准化块乘 `1/sqrt(83)` 或保持原尺度；预测绝对正确率或相对2k/low的带符号正确性增益。每组种子7/17/27，最多12次CPU拟合；基线必须复现EXP-012。目标因素包含输出参数化、损失及检查点损失的整体变化，不声称仅隔离监督标签一项。全部检查点冻结后再评估旧dev；两个开发集均已看过，只能作为机制诊断。沿用原系统筛选条件，不扫lambda，不自动扩到测试/SNR。

**EXP-013结果与本轮终点**：四组顺序为原尺度绝对、均衡尺度绝对、原尺度增益、均衡尺度增益。验证正确数82/79/84/81，旧开发88/91/90/90（均/120）。原尺度增益比原路由两集各多对2题，但平均帧长升至2963.70/2997.07 B，仍不如冻结码率单轴的85/91题与效用。尺度和目标的同图AUC主效应跨集反向，12项探索性检验Holm校正后均不显著，不能确定一个已被解决的因果根因。四组都未过原筛选，不选择最佳种子或最佳开发集来替换主系统。详见[完整分析](../paper/outputs/rgb_selector_factorial_20260922/analysis-output/analysis-report.md)和[中文结果摘要](../code/vqa_semcom_v0/experiments/rgb_selector_factorial/RESULTS.md)。保留普通神经重建、固定档与学习式单轴作为后续候选；任何新一轮须明确新增变量另行授权，本轮不自动扩量。

**前序决定（EXP-011）**：4k/medium 与 high 均为 93/120，视觉 token 约减半，时延降约 17.7%，但没达到预注册的 20% 高效固定门槛。联合 oracle 为 100/120，最强单轴为 97/120、98/120；仅说明值得用训练集数据检验小型控制器能否学到选择规律。不能把 oracle 当作路由结果，也不能直接打开新 300 图选策略。第三步冻结工具已验证此限制并输出 `CONTROLLER_TRAINING_PROTOCOL_NEEDED`。详细结果与数据指纹见 [EXP-011 协议/实现](../code/vqa_semcom_v0/experiments/rgb_rate_visual_budget/README.md) 与[实验总账](EXPERIMENT_LEDGER.md)。

已完成 [EXP-010 冻结协议](../paper/outputs/tdiuc_common_channel_baselines_20260922/PROTOCOL.md) 的有界开发流水线：2400 训练图/题、120 开发图，新 300 图测试继续封存。RSVQA 为 48–52/120，T24/48/96 为 50/52/50；同集 standard Qwen 的普通神经重建 2k/4k/8k 为 87/93/92，原图为 98/120。RSVQA 8k 视觉置乱比正确图片多对一题，不能把弱基线分数直接用作论文优势。开发集 2/120 题的答案不在训练词表中，保留在分母。

有界流水线实际耗时约 22.6 分钟，所有新产物在 `paper/outputs/tdiuc_common_channel_baselines_20260922/` 与服务器同名输出目录，不覆盖旧权重。完整 120 图 × 20 信道种子的扫描、JPEG + Qwen 新推理和正式测试尚未启动；不得将 6 图、144 次连通性 smoke 汇报为完整比较已完成。详见 [Notion 导师汇报](https://app.notion.com/p/3e37a69b8f53814e83dfc8998459efbc)。

任何新实验开始前，先在总账登记：

1. 它对应哪个旧实验；旧结果为何不足以回答当前问题。
2. 只改变什么关键变量，哪些模块训练、哪些冻结。
3. 数据是否同时独立于问题模块与接收端 LoRA 的训练数据。
4. 主预算、主要对照、可接受准确率损失/收益、继续与停止条件。
5. 固定代码与数据清单、优化器更新数、种子、码流计量方法。

优先判断“新增实验能区分哪两种解释”，再决定是否投入算力。不能只因为训练完成、损失下降、换问题后码图改变，或看过答案的搜索存在好例子，就扩大训练。

如果再研究接收器与发送端适配，必须区分“接收器适配收益”和“问题引导收益”，并保留等训练量控制。若只重复既有 TinyCLIP/门控设置而没有处理已知证据缺口，暂不建议扩量。

历史报告中的“后续”均是当时建议，不是自动执行命令。涉及检测器路线时，保留用户先前的 [YOLO26n 对照要求](../paper/outputs/experiment_control_policy_20260915.md)；本次归档不撤销它，也不因此新增检测器实验。
